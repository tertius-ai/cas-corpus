# A checked isomorphism between two presentations of F_25

Finite fields of the same cardinality are abstractly isomorphic, but a
computer-algebra calculation needs an explicit map between the chosen
presentations. Consider

```text
K = F_5[a] / (a^2 + 2)
L = F_5[b] / (b^2 + b + 2).
```

Both quadratic polynomials are irreducible over `F_5`. The element `2b + 1`
in `L` has square `3`, so `a -> 2b + 1` defines an isomorphism. Its inverse
sends `b -> 3a + 2`.

This is not the unique isomorphism. There are exactly two `F_5`-isomorphisms
between these quadratic fields, because the automorphism group of `F_25` over
`F_5` is generated by Frobenius and has order two. The other choice sends
`a -> 3b + 4`, the Frobenius conjugate of `2b + 1`. Specifying the image of
`a` makes the extension unique; the two bare field presentations do not.

The solution constructs both coefficient contexts with their explicit moduli
and asks Noether for a checked isomorphism. It verifies the expected generator
images, explicitly verifies the second Frobenius-related choice, calls the
native isomorphism verifier, and then exhaustively checks both ring operations
and both compositions on the 25-element fields. `isomorphism_to` is a
deterministic choice, not a uniqueness claim. Contexts are never identified
merely because they have the same cardinality.

This is a small adaptation of the finite-field isomorphism problem studied by
Brieulle, De Feo, Doliskani, Flori, and Schost. Their paper includes much larger
benchmark presentations; this case deliberately supplies a bounded correctness
example rather than reproducing a performance benchmark.
